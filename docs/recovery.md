# Recovery

This stack has three recovery surfaces, ordered by ease of use:

1. **Updater Console** at `http://localhost:3003` — "Roll back to previous version" / "Restart signalk-server" / view logs.
2. **Doctor Console** at `http://localhost:3004` — read-only probes + a big "Recover" button that restores Quadlets from the last-known-good snapshot.
3. **`~/.local/bin/signalk-recovery`** — pure-bash SSH safety net. Works with zero containers running.

Use the highest-numbered one that you can still reach.

## Anatomy: where state lives

| Path | What's in it | Backed up by |
|---|---|---|
| `~/.signalk/` | SignalK config, plugins, security | signalk-backup (separate plugin) |
| `~/.signalk-updater/token` | Bearer auth token for the updater (mode 0600) | not backed up; regenerated by reinstall |
| `~/.signalk-updater/hardware.json` | Hardware passthrough config | reproducible from detect-hardware.sh |
| `~/.signalk-updater/operation.lock` | Cross-engine mutex (only present during mutating ops) | transient |
| `~/.signalk-doctor/token` | Bearer auth token for the doctor (mode 0600) | not backed up |
| `~/.signalk-doctor/snapshots/` | Every Quadlet write is snapshotted here (last 10 per file) | this is the backup |
| `~/.signalk-doctor/last-good.json` | The validated last-known-good tag set + snapshot paths | regenerated on each successful switch |
| `~/.config/containers/systemd/signalk-*.container` | Active Quadlets — rewritten by the updater on switch / hardware-apply | mirror in snapshots/ |
| `~/.local/bin/signalk-recovery` | Host-resident bash recovery | installed by the bash installer |

## Scenario: signalk-server is broken but the engines are fine

1. Open Updater Console → "Logs" → look for the error.
2. If a recent version switch went wrong, click "Roll back to previous version".
3. If that fails, open Doctor Console and click "Recover" — this restores Quadlets from the last validated snapshot.

## Scenario: the updater itself is broken (bad self-update, crashloop)

1. Open Doctor Console at `http://localhost:3004`.
2. Click "Recover" — this also restores the updater's Quadlet to the last-known-good snapshot.
3. Wait ~10s for the updater container to restart on the old image.

If the doctor's `Restart=on-failure` + `StartLimit*` hit, the unit goes to `failed` state. Reset it from SSH:

```bash
systemctl --user reset-failed signalk-updater-server.service
systemctl --user start signalk-updater-server.service
```

## Scenario: both engines are down (the worst case)

Open SSH and use the bash recovery script:

```bash
~/.local/bin/signalk-recovery status         # what's running, what's broken
~/.local/bin/signalk-recovery doctor         # full diagnostics dump
~/.local/bin/signalk-recovery rollback-all   # restore every Quadlet from last-known-good
```

`rollback-all` will:

1. Copy the newest `~/.signalk-doctor/snapshots/*-<unit>.container` over each active Quadlet.
2. `systemctl --user daemon-reload`.
3. `systemctl --user try-restart` each affected service.

No containers need to be running for this to work — it's pure bash + systemd.

## Scenario: corrupted state files

The `~/.signalk-doctor/snapshots/` directory is the source of truth for recovery. If the snapshots themselves are gone:

- Re-run the bash installer (`curl -fsSL ... | bash`). It is idempotent and will re-pull images and re-write fresh Quadlets, marking the new state as "bootstrap-complete" in `last-good.json`.
- This preserves `~/.signalk/` (your SignalK config + plugins) and `~/.signalk-backup/` (your backup repo if present).

## Journald retention

The installer drops `/etc/systemd/journald.conf.d/signalk.conf` with `SystemMaxUse=500M` and `MaxRetentionSec=14day`. On a Pi this prevents the SD card from filling.

If you skipped that step (sudo unavailable at install time), apply it later:

```bash
sudo tee /etc/systemd/journald.conf.d/signalk.conf >/dev/null <<EOF
[Journal]
SystemMaxUse=500M
MaxRetentionSec=14day
EOF
sudo systemctl restart systemd-journald
```

## When even SSH is gone

If you can't even SSH:

- For a boat: physical access. A USB stick with the install.sh + the bash recovery script copied to `~/.local/bin/signalk-recovery` will get you back into the stack from a freshly-installed Linux session.
- The fallback is always `curl -fsSL https://dirkwa.github.io/signalk-universal-installer/installer/linux/install.sh | bash` — the installer is idempotent and will heal a half-broken state.

## What is NOT recoverable from these mechanisms

- **A wiped `~/.signalk/`** — only [signalk-backup](https://github.com/dirkwa/signalk-backup) can restore that. The recovery surfaces here are for the **container stack** that runs around signalk-server, not signalk-server's data.
- **Lost auth tokens.** If you delete `~/.signalk-updater/token`, the Updater Console becomes inaccessible (UI gets 401s on every mutating call). Re-run the installer to regenerate.
